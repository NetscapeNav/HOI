# J2: синхронизированный доступ к списку

## Реализация `CustomList`

`CustomList` — реализация односвязного списка.

Каждый элемент списка хранит:

- строковое значение;
- ссылку на следующий элемент;
- собственный `ReentrantLock`.

В начале списка находится служебный узел `head`.

Добавление нового элемента выполняется в начало списка. Для этого блокируется только `head`, после чего новый узел вставляется сразу после него.

Сортировка выполняется несколькими дочерними потоками. Каждый поток бесконечно выполняет полные проходы пузырьковой сортировки, где один шаг сортировки — сравнение двух соседних элементов и возможная их перестановка.

При перестановке изменяются ссылки между узлами:

```text
previous -> first -> second
```

преобразуется в:

```text
previous -> second -> first
```

Для выполнения одного шага блокируются три последовательных узла:

```text
previous
first
second
```

Блокировки всегда захватываются в направлении от головы списка к хвосту. Это предотвращает возникновение взаимной блокировки между сортирующими потоками.

После выполнения шага все блокировки освобождаются, а задержка между шагами выполняется уже без них. Поэтому главный поток может в это время добавлять новые элементы или выводить текущее состояние списка.

Для вывода создаётся снимок списка. При обходе одновременно блокируются только соседние узлы. Полученные значения копируются во временный `ArrayList`, после чего вывод выполняется через обычный цикл `for-each`.

## Реализация `MyArrayList`

Вторая реализация использует стандартный `ArrayList`, обёрнутый в:

```java
Collections.synchronizedList(...)
```

Добавление элемента выполняется методом:

```java
list.add(0, value);
```

При сортировке сравниваются соседние элементы.

Каждый шаг выполняется внутри:

```java
synchronized (list) {
    ...
}
```
поскольку несколько операций `get()` и `set()` должны выполняться атомарно.

Внутри блока выполняются:

1. проверка границ списка;
2. задержка внутри шага;
3. чтение двух элементов;
4. сравнение;
5. возможная перестановка.

После завершения шага монитор списка освобождается. Задержка между шагами выполняется уже вне блока `synchronized`.

Таким образом, весь проход сортировки целиком не блокирует список, однако одновременно выполнять внутреннюю часть шага может только один поток.

Для вывода под блокировкой списка создаётся его копия, после чего `iterator()` работает уже с этой копией.

## Теоретический расчёт количества шагов

Для измерений использовались следующие параметры:

- количество элементов: `100`;
- время работы: `30 секунд`;
- задержка внутри шага: `100 мс`;
- задержка между шагами: `100 мс`;
- количество потоков: `1` или `4`.

Один полный проход по списку из 100 элементов содержит:

```text
99 шагов
```

Однако измеряется не количество полных проходов, а суммарное количество выполненных шагов за заданное время.

Для одного потока время одного шага приблизительно равно:

```text
100 мс + 100 мс = 200 мс
```

Следовательно, за 30 секунд один поток теоретически может выполнить:

```text
30 / 0,2 = 150 шагов
```

### `CustomList`

Для одного потока:

```text
150 шагов
```

При четырёх потоках отдельные шаги теоретически могут выполняться параллельно, так как используются блокировки отдельных узлов.

Максимальная теоретическая оценка:

```text
4 * 150 = 600 шагов
```

Это является верхней границей.

### `MyArrayList`

Для одного потока оценка также составляет:

```text
150 шагов
```

При четырёх потоках внутренняя задержка длительностью `100 мс` выполняется под общей блокировкой списка.

Следовательно, одновременно внутреннюю часть шага может выполнять только один поток.

Максимальная пропускная способность внутренней части составляет:

```text
1 / 0,1 = 10 шагов в секунду
```

За 30 секунд:

```text
30 * 10 = 300 шагов
```

Таким образом, для четырёх потоков теоретическая верхняя граница составляет примерно:

```text
300 шагов
```

## Результаты измерений

| Реализация | Количество потоков | Теоретическая оценка | Фактическое количество шагов | Шагов в секунду |
|---|---:|---:|---:|---:|
| `CustomList` | 1 | около 150 | 148 | 4,93 |
| `CustomList` | 4 | до 600 | 297 | 9,90 |
| `MyArrayList` | 1 | около 150 | 147 | 4,90 |
| `MyArrayList` | 4 | около 300 | 297 | 9,90 |

Фактическое количество шагов немного меньше теоретического из-за затрат на выполнение инструкций, работу с блокировками и планирование потоков.

Для одного потока результаты обеих реализаций практически совпадают, поскольку основную часть времени составляют искусственные задержки.

При четырёх потоках `MyArrayList` ограничен общей блокировкой списка, поэтому одновременно выполнять шаг может только один поток.

`CustomList` теоретически допускает параллельную работу потоков на разных участках списка. Однако в данной реализации каждый шаг начинается с прохода от головы списка, поэтому потоки часто конкурируют за одни и те же узлы. В результате фактическое число шагов оказалось значительно меньше максимальной теоретической оценки.
